## Bounded Sol adjudication

Use one episodic **GPT-6.1 Sol · Medium** adjudicator only when the decision has unusually high leverage and Luna builders/critics leave a material ambiguity: macro acceptance, substantive disagreement, consequential information architecture, cross-surface conflict, or an owner-requested deep review. One active Sol specialist maximum by default; it must not spawn Sol agents or act as project manager.

Before dispatch, Luna writes one decision question and a compact capsule containing only:

1. the decision question and relevant owner direction;
2. exact authoritative Figma/source references and necessary screenshots;
3. factual constraints;
4. Luna builder and critic conclusions;
5. the specific uncertainty;
6. the requested output.

Aim for 1,000–3,000 useful words plus only necessary visual evidence. Link durable references instead of importing project history. Ask one question per invocation.

Expected response: **Decision, Why, Preserve, Change, Acceptance test.** Luna translates the judgment into work. Sol does not implement a self-review loop, poll, monitor, maintain documentation, or decide ordinary next steps. Complete the one bounded task and return the agent to idle immediately; interrupt it if work would otherwise continue past the answer.

**Good Sol use:** “Does this expanded Food Tracker story cover the full product at the macro level? Name only remaining macro gaps.”

**Do not use Sol for:** Git, docs, node maps, routine Figma edits, React/CSS, research extraction, tests/builds/lint, Playwright, captures, browser comparison, responsive/accessibility fixes, deployment, status, waiting, or ordinary sequencing. Those remain Luna work.
