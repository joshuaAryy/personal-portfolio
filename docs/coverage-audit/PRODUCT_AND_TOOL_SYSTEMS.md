### Immutable implementation check (Food Tracker)

I checked the public `main` head with `git ls-remote` and inspected source at immutable commit [`4674e78b2ddcd705be323f9bfafb23b95b7848ea`](https://github.com/joshuaAryy/food-tracker/commit/4674e78b2ddcd705be323f9bfafb23b95b7848ea). These are implementation files at that commit, not a claim that every path was deployed in a public release or that the portfolio capture shows this UI.

- **Logging, serving, history, editing:** Mobile food logging supports manual entry, catalog-backed entries, external food candidates, reusable foods, recent foods, and explicit update/delete actions in [`food-log.tsx`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/mobile/src/app/food-log.tsx#L851-L1030). The same screen links meal text, photo, library, recipes, mixed meal, and barcode flows (lines 1513–1621). Serving math is backend-owned: `calculateAuthoritativeServing` resolves a requested unit/quantity against basis and serving options, scales nutrition, applies permitted overrides, and records a serving snapshot with provenance/resolution in [`serving-resolution.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/foodLogs/serving-resolution.ts#L227-L337). History lists date-scoped food records and opens a selected row for edit; the API update path recalculates snapshot-backed serving changes from that snapshot, while recipe/mixed-meal logs restrict edits to metadata; delete is user-scoped in [`routes.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/foodLogs/routes.ts#L1721-L1927). So “immutable history” needs precision: the nutrition basis is preserved in a snapshot, but user-authorized edits/deletion exist; recipe and mixed-meal constraints differ.
- **Insights:** Mobile code branches Simple and Complex presentation in [`insights.tsx`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/mobile/src/app/%28tabs%29/insights.tsx#L322-L375). Simple has compact overview and recommendations; Complex has Overview, Nutrients, and Recommendations tabs and links to trend exploration. Separate source files implement calories/macros, weight, hydration, logging consistency, nutrient coverage, custom comparisons/ranges, saved views, and deterministic forecasts (for example [`analytics/trends/service.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/analytics/trends/service.ts#L38-L80)). Source code and README support an implemented mobile Insights subsystem, not a claim that every analytic is in Simple mode or every feature has external-user rollout.
- **Photo / AI logging pipeline:** This is genuine image-model code, not an inference from the README. The authenticated API accepts JPEG with size/type validation and per-user rate limits in [`ai/routes.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/ai/routes.ts#L50-L109). `GeminiPhotoAnalysisProvider` sends image bytes to the configured Gemini `generateContent` model with a structured response schema and constrained instructions: identify visible food/preparation, decompose only independently loggable components, estimate useful quantities, and do **not** invent calories/macros, conversions, IDs, trusted matches, or reasoning ([`photo-provider.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/ai/photo-provider.ts#L691-L769)). The API then maps those suggestions into local/external food retrieval candidates; a separate optional Gemini adjudication call may select only a supplied candidate or return no decision and may supply bounded low/medium-confidence calories/macros when enabled and context exists ([`photo-analysis.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/ai/photo-analysis.ts#L1193-L1232), [`photo-candidate-adjudication.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/ai/photo-candidate-adjudication.ts#L269-L280), enablement flags in [`photo-config.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/ai/photo-config.ts#L120-L160)). The estimate is explicitly tagged `source: ai_estimate`, `trust: low`, and editable; server validation bounds values and checks calorie/macro consistency ([`photo-nutrition-estimate.ts`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/api/src/modules/ai/photo-nutrition-estimate.ts#L22-L81)). Mobile review requires the user to classify each row as trusted, estimated, or excluded; confirmation sends one atomic save and excludes selected rows from logs ([`review.tsx`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/mobile/src/app/photo-log/review.tsx#L89-L151), [`confirm.tsx`](https://github.com/joshuaAryy/food-tracker/blob/4674e78b2ddcd705be323f9bfafb23b95b7848ea/apps/mobile/src/app/photo-log/confirm.tsx#L81-L120)). Accurate short form: **AI suggests foods and portions from a photo; backend retrieval and serving rules ground trusted rows; uncertain rows remain visibly low-trust estimates for user review.** It does not autonomously create final trusted nutrition.
- **Implemented vs validated/released:** Pinned `main` contains the routes, providers, UI, persistence, and analytics source paths above. The README says photo logging was completed earlier, while also explicitly marking photo candidate adjudication and the optional API-unavailable check `Not tested`; do not imply those specific failure/manual gates passed. The repository describes a validated Railway staging environment and defers paid Apple distribution/TestFlight/App Store; code presence is not proof of public-store release. If claiming “shipped,” specify the code/staging/device boundary and verify the exact phase artifact first.
