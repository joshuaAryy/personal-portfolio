## Status and sync rules

- Owner rejection or reopening immediately supersedes prior pass clearance. A critic’s scoped “CLEAR” is not owner approval or whole-surface acceptance.
- Use explicit statuses: DESIGNING, NEEDS REDESIGN, REVIEW CANDIDATE, IMPLEMENT READY, IMPLEMENTED, NEEDS SYNC. Do not infer acceptance from pass count.
- Read implementation, validation, approval, and blocker status separately: **IMPLEMENTED** means the source exists; **NEEDS RENDER SYNC** means current supported-browser comparison is still missing; **OWNER REVIEW OPEN** means owner approval remains pending; **ACTUAL BLOCKER** names a specific unavailable dependency. The current browser dependency blocks render validation only; portfolio execution is not blocked.
- Begin implementation when structure, content hierarchy, and interaction intent are stable enough to translate. Owner approval is required for final completion, not every implementation pass.
- Converge through implement → render the actual site → compare with Figma/reference → critique → correct → owner review → freeze. Passes or agents alone are not progress.
- Browser validation status: **SUPPORTED BROWSER UNAVAILABLE / BROWSER RENDER VALIDATION BLOCKED / PORTFOLIO EXECUTION CONTINUES.** Browser-dependent rows remain `NEEDS RENDER SYNC`; non-browser design, documentation, asset, critique, and implementation work continues. See [RENDER_VALIDATION_QUEUE.md](RENDER_VALIDATION_QUEUE.md). Do not infer parity from tests, builds, HTTP responses, source inspection, Figma screenshots, or stale captures.
- Each of the six long-form stories now has a 1920x1080 production/client frame and an indexed, unclipped full-page review clone from the same authored content. Keep clones synchronized after source edits; do not treat inspectability as acceptance.
